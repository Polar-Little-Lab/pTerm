# 터미널 도구 사용 안내

이 문서는 `feat/macos-terminal-workflows`의 개발 중 기능을 설명합니다. v1.0.0 배포 앱에는 포함되어 있지 않습니다.

상단 **터미널 도구**를 누르거나 **⌘ K**에서 기능 이름을 검색합니다. 터미널 검색은 **⌘ F**로도 열 수 있습니다.

## 작성과 다중 전송

명령을 작성하고 연결된 세션을 선택한 뒤 **전송 대상 확인 → 확인한 대상에 전송**을 누릅니다. 전송 직전에 연결이 종료된 세션은 제외됩니다. 붙여넣기에 줄바꿈이 포함되면 셸에서 명령이 실행될 수 있습니다. 전송 결과는 원격 명령의 성공 여부를 뜻하지 않습니다.

## 검색

현재 세션의 스크롤백을 검색합니다. 대소문자와 정규식을 선택할 수 있으며 Enter/Shift+Enter 또는 이전/다음 버튼을 사용합니다. 결과는 최대 2,000개입니다. 오래 걸리는 정규식은 500ms 후 종료합니다. 이미 스크롤백에서 제거된 출력은 검색하지 않습니다.

## 기록과 재생

**기록 시작** 이후의 수신 출력만 메모리에 보관합니다. 최대 1 MiB 또는 4,096개 청크이며, 초과 시 오래된 기록을 버리고 표시합니다. 일반 로그, Hex, RTF, 재생용 JSON으로 저장할 수 있습니다. RTF는 ANSI 제어 코드를 제거한 텍스트를 저장하며 한글·이모지와 줄바꿈을 유지합니다. 터미널의 색상·강조 모양을 그대로 재현하지는 않습니다. **로그 다시 보기**는 pTerm JSON 로그를 읽기 전용으로 순서대로 표시합니다. 원본 출력 시간 간격을 재현하지는 않습니다.

기록에는 서버가 출력한 민감한 정보가 포함될 수 있습니다. 세션을 닫기 전에 필요한 기록을 저장하세요.

## 자동화

JSON 배열의 세 가지 단계가 있습니다.

```json
[
  {"send":"echo ready\n"},
  {"expect":"ready","timeout":10000},
  {"wait":500}
]
```

- `send`: 현재 세션에 문자열을 붙여넣습니다.
- `expect`: 최근 전송 이후의 출력에 문자열이 나타나기를 기다립니다. 기본 10초, 최대 60초입니다.
- `wait`: 최대 30초까지 대기합니다.

최대 200개 단계, 전체 64 KiB입니다. 실행 전 대상과 단계를 확인합니다. 중지 버튼, 도구 화면 닫기, 연결 종료, 전송 실패, 출력 대기 시간 초과 시 실행이 멈춥니다. 이미 전달한 명령은 취소하거나 되돌리지 않습니다. JSON 시나리오 외에 Python/Node 세션 스크립트를 지원합니다. [연결·실행과 스크립트 안내](native-connections.md)를 참조하세요.

입력 기록은 비밀번호를 포함한 입력을 기록할 수 있으므로 필요한 작업 동안만 켜고 저장 전 검토하세요. 세션 단축키는 Ctrl+Option+문자로 등록합니다. 규칙과 기록은 현재 세션의 메모리에만 남습니다.

## 터널

연결된 SSH 세션에서 로컬·원격 포트 포워딩 또는 SOCKS5 동적 포워딩을 시작합니다. 로컬 포트 0은 빈 포트를 자동 선택합니다. 로컬 리스너는 `127.0.0.1`에 바인딩되고 원격 리스너도 서버에 `127.0.0.1` 바인딩을 요청합니다. 실제 서버의 GatewayPorts 정책이 영향을 줄 수 있습니다. 원격 리슨 포트는 1–65535로 지정합니다. SSH 종료 시 연결된 터널과 스트림도 정리됩니다.

SOCKS5는 무인증 CONNECT만 지원합니다. SOCKS4와 UDP는 제공하지 않습니다.

## 호스트 이전

⌘ K → **호스트·저장 명령 가져오기 / 내보내기**에서 JSON으로 이전합니다. Vault가 열린 상태에서 사용할 수 있습니다. 비밀번호와 서버 지문은 제외됩니다. 저장 명령에 직접 작성한 비밀 값은 자동 제거되지 않습니다. 가져오기는 미리보기 후 새 항목으로 추가하며 기존 항목을 덮어쓰지 않습니다.

## 화면과 닫기 보호

화면 탭에서 현재 세션의 글꼴 크기·커서·닫기 보호를 설정합니다. 닫기 보호는 탭/분할 영역을 실수로 닫는 것을 방지하는 옵션이며, 앱 종료·Vault 잠금·서버 연결 종료를 막는 보안 기능이 아닙니다. 이 설정은 다음 실행에 복원되지 않습니다.


## 자동 파일 로그와 회전

**기록·Hex → 파일에 연속 기록**에서 폴더를 선택하고 시작한다. 메모리 기록과 별개로 수신 데이터를 계속 파일에 쓴다. 탭에는 기록 중 표시와 오류가 나타난다. 시각 옵션을 끄면 수신 바이트 그대로, 켜면 UTF-8로 해석된 수신 청크별 시각을 저장한다.

실행마다 선택한 폴더 아래에 별도의 `pterm-UUID` 디렉터리를 만든다. 파일당 1–100 MiB, 현재 실행에서 1–100개 파일을 보존한다. 한 파일의 상한을 넘기기 전에 다음 파일로 전환하며, 보존 개수를 넘으면 **현재 실행이 만든 가장 오래된 파일만** 삭제한다. 이전 연결의 로그와 다른 파일은 자동 삭제하지 않는다. 로그 폴더와 파일 권한은 각각 0700/0600이며 로그 자체는 평문이다.

전송 중 쓰기 대기열은 최대 4 MiB 또는 4096개 청크다. 작은 출력이 몰리는 경우에도 메모리와 대기열 처리량을 제한한다. 디스크 오류나 대기열 초과 시 기록을 중지하고 오류를 표시하며, 아직 쓰지 못한 대기 데이터는 폐기한다. 무제한으로 메모리에 쌓거나 누락을 숨기지 않는다. 일반적인 중지·탭 종료 시에는 대기 중인 쓰기를 마친 뒤 파일을 동기화한다. 정상 앱 종료도 남은 기록을 저장하도록 처리한다. 강제 종료·장치 오류 시 아직 쓰지 못한 데이터는 유실될 수 있다.

오류가 발생하면 파일 정리가 끝날 때까지 다시 시작할 수 없다. 오류 표시 처리에 문제가 생겨도 파일 정리와 중지 완료 처리는 계속된다.

다음 연결부터 자동으로 시작하려면 **세션 기본값·상속 → 파일 기록·용량 제한**에서 설정한다. 저장소를 잠금 해제하기 전의 첫 로컬 셸에는 저장된 기본값을 적용하지 않는다.

## 기본값·그룹·호스트 상속

**⌘ K → 세션 기본값·그룹·호스트 설정 상속**, 또는 **터미널 도구 → 화면 → 기본값·그룹·호스트 상속 설정**에서 연다. 저장소 잠금 해제가 필요하다.

우선순위는 기본값 → 호스트 그룹 → 개별 호스트다. 각 항목의 직접 설정 체크를 끄면 상위 값을 따른다. 글꼴·줄 높이·스크롤백·커서·닫기 보호·자동 기록·SSH 시작 명령을 설정할 수 있다. 저장은 다음 연결부터 적용되고 현재 세션은 즉시 바뀌지 않는다. 로컬·외부 엔진 연결은 전체 기본값만 사용한다.

JSON 내보내기는 호스트의 최종 적용 값을 포함한다. 가져온 호스트에는 그 값을 직접 설정으로 저장하므로 기존 작업공간의 기본값이나 그룹 설정은 바꾸지 않는다. **가져온 자동 명령과 자동 파일 기록은 비활성화된다.** 내용과 경로를 검토한 뒤 호스트 설정에서 직접 켠다. 원본의 동적인 상속 구조 자체를 복원하는 형식은 아니다.

## 자동 명령 트리거

**트리거 → 동작 → 자동 명령 전송**을 선택한다. 감지 문자열, 전송 문자열, Enter 추가 여부, 최대 횟수(1–10회), 최소 간격(1–60초)을 입력하고 검토 후 등록한다. 기본값은 1회·5초다. 실제 입력을 보내므로 Enter나 줄바꿈은 명령을 실행할 수 있다.

청크 경계에 걸친 문자열도 감지한다. 이미 전송 중인 규칙은 다시 실행하지 않고, 명령 출력이 감지 조건에 다시 걸리더라도 횟수·간격 제한을 유지한다. 전송 실패 시 해당 규칙을 비활성화한다. **자동 전송 모두 중지**는 아직 전송하지 않은 작업도 취소한다. 이미 전달된 입력은 되돌리지 않는다. **횟수 초기화·다시 준비**는 사용자가 명시적으로 다시 허용하는 동작이다.

규칙은 세션 메모리에만 존재한다. 도구 화면을 닫아도 유지되고 세션을 닫으면 사라진다. 문자열 감지 방식이며 정규식 트리거나 임의 외부 스크립트 호출은 지원하지 않는다.

## SSH 연결 후 명령

상속 설정의 **SSH 연결 후 자동 명령**에서 사용 여부와 명령을 지정한다. 앱 내부 SSH 인증 및 셸 연결이 완료된 후 한 번 실행한다. 마지막 줄에 Enter를 추가하고, 자동 재연결에도 새 세션마다 실행한다. 최대 16 KiB이며 기존 입력 대기열 순서를 따른다. 연결 종료나 입력 실패는 오류로 표시한다.

기본값·그룹에 설정하면 해당 범위의 모든 내부 SSH 호스트에 적용된다. 외부 OpenSSH 프로세스·로컬 셸·시리얼에는 이 시작 명령을 보내지 않는다. 비밀번호 등 인증 정보는 넣지 않는다. 명령 전송 완료는 서버에서 명령이 성공했다는 뜻이 아니다.
