# SSH 인증 정보 저장

2026-10-25 · 1.0.0 통합 기능

호스트 편집과 인증 재입력 화면의 비밀번호 저장 / 키 암호 저장 옵션으로 선택합니다. 기본값은 저장 안 함이며, 이미 저장한 호스트는 저장 상태를 표시합니다. 저장된 실제 값은 편집 입력란에 채우지 않습니다. 빈 입력은 기존 값을 유지하고 새 입력은 교체합니다. 별도 삭제 버튼 또는 저장 옵션 해제 후 저장으로 제거합니다.

## 저장과 사용

기존 version 1 Workspace에 선택적 `credentials` 목록을 추가했습니다. 호스트에는 인증 정보를 넣지 않으므로 세션·탭·호스트 복제에 비밀번호가 전달되지 않습니다. 목록은 전체 Workspace와 함께 XChaCha20-Poly1305로 암호화해 SQLite에 저장하며, 암호화 키는 기존 macOS Keychain 키를 재사용합니다. 인증 정보마다 Keychain 항목이나 추가 승인 요청을 만들지 않습니다. 잠금 해제된 동안만 메모리에 보관하고, 잠글 때 Workspace와 입력값·진행 중 경로를 비웁니다. JavaScript 문자열의 메모리 완전 소거는 보장하지 않습니다.

호스트 ID와 주소·포트·사용자·인증 방식·키 경로·Bastion ID를 결합한 scope가 일치할 때만 사용합니다. 수정·삭제 후 저장 시 맞지 않는 인증 정보는 제거합니다. 즐겨찾기·그룹·서버 지문 저장은 인증 정보를 유지합니다. 개인 키 파일은 기존 위치에서 읽으며 복사하지 않습니다. 인증 정보가 없는 이전 저장소도 그대로 열 수 있습니다.

각 Bastion 단계는 자신의 인증 정보를 조회합니다. 대상 서버에 일회성으로 입력한 비밀번호가 Bastion으로 전달되지 않습니다. 서버 지문 확인은 기존 SSH 백엔드가 인증 전에 수행합니다. 인증 실패 후에는 입력값을 비우고 재입력을 받습니다. 재입력한 값은 저장 선택 상태에서 연결 성공 후 저장합니다. 호스트 편집의 명시적인 저장은 접속 성공 여부와 관계없이 요청한 값을 저장합니다.

## 검증

- JavaScript 65개 테스트 통과: 실제 App 연결 핸들러의 다단 경유·저장 값 자동 사용·실패 후 교체·일회성 인증, scope 변경·호스트 삭제·복제 방지, 이전 형식 호환 포함.
- Rust Vault 테스트 7개 통과, 명시적 Keychain 테스트 1개 제외. SQLite 재개방 후 인증 정보 복원과 디스크 평문 미포함, 잘못된 키 거부 확인.
- 전체 Rust release 테스트 35개 통과, 명시적 실행용 테스트 4개 제외. SSH 암호화 개인 키 인증·SFTP·로컬 PTY 검증 포함.
- 후속 네이티브 UI 검증을 완료했습니다. Frost에서 저장, 자동 재접속, 재실행 후 저장 상태 복원, 실패 후 재입력과 교체, Bastion 연결을 확인했습니다. 삭제 버튼 표시는 확인했으며 삭제 동작은 자동 테스트로 검증했습니다. [촬영 기록](guide-capture-verification.md).
- TypeScript·Vite 및 macOS arm64 release 빌드, ZIP 검사와 압축 해제 후 ad-hoc 서명 검증 완료.
